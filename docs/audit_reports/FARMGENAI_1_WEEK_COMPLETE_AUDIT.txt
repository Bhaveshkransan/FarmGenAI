================================================================================
PRIMARY FILES:
- backend/services/buyer_workflow_service.py (734 lines)
- backend/routes/buyer_requirement_routes.py (424 lines)
- backend/agents/buyer_graph.py (892 lines)
- frontend/src/pages/negotiation/NegotiationRoom.tsx (1,871 lines)

KEY CAPABILITIES IMPLEMENTED:
1. Buyer Workflow State Machine:
   Tracks requirement-scoped memory across:
   - selected_agents: e.g. ["FARMER", "TRANSPORT"]
   - current_agent: Active executing agent
   - completed_agents: Successfully executed agents
   - failed_agents: Failed agents
   - pending_agents: Awaiting upstream dependencies
   - farmer_deal: Authoritative contract terms verified against DB
   - agent_outcomes: Results from downstream agents
   - conversation_context: Business interaction timeline
   - audit_logs: Cryptographic & explainable decision audit trail

2. Authoritative Farmer Deal Gate:
   Method: verify_farmer_deal_authoritative(deal_id)
   - Directly queries PostgreSQL negotiations table via Database.get_negotiation_async.
   - Requires status == "DEAL" or "COMPLETED".
   - Verifies price > 0 and quantity > 0.
   - Explicitly rejects deals with status WITHDRAWN, CANCELLED, or EXPIRED.
   - Front-end flags or LLM assertions are completely untrusted.

3. Explainable Valid-Next-Action Engine:
   Method: get_valid_next_actions(state)
   Returns exact valid actions with dual explanations:
   - "Why this agent?": e.g., "Transport is selected, Farmer deal is verified,
     and Transport is the next permitted dependency."
   - "Why not this agent?": e.g., "Warehouse is pending because Transport must
     complete dispatch planning before storage handoff."

4. Deterministic Buyer Policy Interface:
   - Base class: BuyerPolicy (ABC)
   - Active implementation: DeterministicBuyerPolicy
   - Clean architecture prepared for future RL policy insertion without
     altering core workflow state mechanics.

5. Idempotent Step Execution:
   - Endpoint: POST /requirements/{id}/workflow/step { action: 'TRANSPORT' }
   - Checks if action is currently eligible in get_valid_next_actions.
   - Once executed, moves agent to completed_agents.
   - Immediate second click throws ValueError and returns HTTP 400 Bad Request.
   - Prevents duplicate fleet bookings or double-spend.

8. SUBSYSTEM 6: MATCHING ENGINE & 8-FACTOR NRV FORMULA
================================================================================
PRIMARY FILE:
- backend/services/matching_service.py (302 lines)

CANONICAL 8-FACTOR NET REALIZABLE VALUE (NRV) MODEL:
Unified identically across matching_service.py and LangGraph nodes:
1. Base Price Compatibility (20%):
   - 20 pts if Target Price >= Minimum Price
   - Scaled 10-20 pts if Max Price >= Minimum Price
   - 0 pts if outside budget
2. Quantity Fulfillment (20%):
   - min(Available, Requested) / max(Available, Requested) * 20 pts
3. Distance Proximity (15%):
   - max(0, 1.0 - Distance_km / 600.0) * 15 pts
4. Trust & Reliability (15%):
   - min(Trust_Score / 5.0, 1.0) * 15 pts
5. Quality & Grade Match (10%):
   - 10 pts for exact grade match; 8 pts for acceptable downgrade; 4 pts for mismatch
6. Urgency & Spoilage Match (10%):
   - 10 pts for high-urgency buyer matched with perishable produce (<= 3 days)
   - 6 pts baseline
7. Transport Cost Efficiency (5%):
   - (1.0 - Estimated_Freight / Budget) * 5 pts
8. Storage Cost Efficiency (5%):
   - 5 pts if direct consumption; 2 pts if long-term holding required

9. SUBSYSTEM 7: ECONOMIC LANDED-COST & APMC CESS OPTIMIZER
================================================================================
PRIMARY FILE:
- backend/services/buyer_orchestrator.py (Lines 559-567 & 792)

LANDED COST FORMULATION:
Landed Cost per kg = Base Negotiated Price + Freight per kg + APMC Statutory Cess

Where:
- Freight Total = max(Rs.650.00, (Distance_km * Rs.6.50) + (Quantity_kg * Rs.0.35))
- Freight per kg = Freight Total / Quantity_kg
- APMC Cess per kg = Base Negotiated Price * 0.01 (1% statutory Maharashtra APMC cess)
- Total Landed Cost = Landed Cost per kg * Quantity_kg

WINNER RANKING LOGIC (Line 792):
executable_deals.sort(key=lambda d: (d["landed_cost_per_kg"], -d["match_score"]))

EMPIRICAL PROOF OF LOGISTICS ADVANTAGE:
- Farmer A (Distant, 450 km):  Base = Rs.50.00/kg -> Landed Cost = Rs.53.78/kg
- Farmer B (Nearby, 60 km):    Base = Rs.51.00/kg -> Landed Cost = Rs.52.55/kg
RESULT:
The Buyer Agent automatically selects Farmer B as #1 Winner, proving that
logistics costs override nominal base pricing.
